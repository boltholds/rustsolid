# RustSolid v0.21 — first committed analytic curved Boolean

This release adds a constrained, **real analytic cylindrical through-hole**
result, built as a B-rep with circular edges, a cylindrical surface,
coedge-specific UV trims, two inner face loops, a periodic seam and a
single connected shell of genus 1.

The geometry is not generated by subtracting triangle meshes or
approximation of a curved face. Tessellation is a separate viewport product.

## Executable Boolean contract

`BooleanKernel::apply(left, right, Difference)` accepts:

- Left operand: a strictly certified exact axis-aligned six-face block.
- Right operand: a validated circular cylinder with axis **+Y**.
- Cylinder bottom exactly at the block bottom; cylinder height equals the
  block height within the local resolution.
- Its circular cross-section is strictly contained inside all four
  block side planes, with clearance exceeding the local tolerance.

For this case the output is
`BooleanOutcome::Analytic(ThroughHoleBrep)`. A right operand that does not
fully cross the block, a rotated/oblique axis, tangency to the box boundary,
oversized/degenerate radius or general non-box shapes are rejected.

The same Boolean may be requested through two `BrepArena` instances.
Operands are never modified.

`TopologyDeltaPlan` is **not** the execution mechanism. The special-case
analytic builder is independently validated and does not lift the
`TopologyDeltaPlan::can_apply == false` guard.

## Canonical topology

The resulting B-rep has:

| Entity | Count |
| --- | ---: |
| Vertices | 10 |
| Edges | 15 |
| Coedges | 30 |
| Faces | 7 |
| Loops | 9 |
| Inner face loops | 2 |
| Shells | 1 |
| Circular edges | 2 |
| Periodic seam edges | 1 |

The six original cuboid planar surfaces remain canonical. Bottom and top
faces have one outer rectangular loop and an independent inner circular
loop. The seventh face is an actual `Surface3::Cylinder` with a periodic
`u=[0,2π]`, bounded axial `v=[0,height]` domain and four directed
coedges, including both orientations of the single physical seam.
Two separate 2D circular pcurves bind the corresponding cap holes to
their actual supporting planes.

Because a face with an inner loop is topologically an annulus,
**Euler characteristic is `V - E + F - inner_loops`** for the current
two-manifold cellular representation. Here `10 - 15 + 7 - 2 = 0`, giving
genus `g=(2-χ)/2=1`. The generic `BrepModel` summary now accounts for
inner loops, and validation rejects mismatches between declared
outer/inner loop roles and actual face loop order. The polyhedral
`Solid` validator retains its old genus-zero restriction.

For block dimensions `w,h,d`, removed cylinder radius `r` and
cross-section centered at `cx,cz`:

`V = w*h*d - π*r²*h`

`S = 2*(w*h+w*d+h*d) - 2*π*r² + 2*π*r*h`

The centroid is computed from exact primitive mass moments, using the
removed cylindrical volume. Mesh triangle counts cannot alter these
properties.

## Atomic parameter editing

`ThroughHoleBrep::begin_edit()` stages `set_radius` and `set_center`.
The entire new canonical analytic model is rebuilt and independently
validated before committing. An invalid operation cannot publish partial
topology or change revision or Undo/Redo history, even if its staging
error is ignored.

`ThroughHoleBrep::undo()` and `redo()` restore previously validated
parameter snapshots, increasing runtime revision monotonically. The
history limit on local edits is 128 steps.

`BrepArena::update_hole(HoleParameters)` performs the same candidate
edit plus **sparse generational identity reconciliation before
publication**, ensuring that fixed semantic elements preserve their
arena handles while revision-tagged snapshots expire. Arena Undo/Redo
also works for these parameter edits. General mixed Euler + curved
surface mutation remains future work.

## Rust usage

```rust
use rustsolid::{
    BooleanKernel, BooleanOperation, BooleanOutcome, BrepBody,
    BrepArena, CylindricalBrep, GeometryTolerance, Point3, Solid,
};
let block=Solid::block(Point3{x:-3.,y:-1.,z:-3.},6.,4.,6.)?;
let drill=CylindricalBrep::upright(Point3{x:0.,y:-1.,z:0.},
    1.,4.,GeometryTolerance::default())?;
let boolean=BooleanKernel::apply(
    &BrepBody::from(block),
    &BrepBody::from(drill),
    BooleanOperation::Difference
).map_err(|e|rustsolid::GeometryError::InvalidEdit(e.to_string()))?;
if let BooleanOutcome::Analytic(hole)=boolean.outcome {
    assert_eq!(hole.model().summary().genus,1);
    let mut arena=BrepArena::from_through_hole(hole)?;
    arena.validate()?;
}
```

## geometry.v1

The existing `boolean` JSON endpoint now accepts an analytic-cylinder
right operand for the constrained through-hole case:

```json
{"operation":"boolean","mode":"difference",
 "left":{"kind":"block","origin":[-3,-1,-3],
         "width":6,"height":4,"depth":6},
 "right":{"kind":"analytic_cylinder","origin":[0,-1,0],
          "radius":1,"height":4}}
```

Its response contains `representation:"analytic_cylindrical_through_hole"`,
`genus:1`, `topology_committed:true`, an analytic B-rep metadata summary,
7 source-face lineage records, and an independently generated display mesh
under the normal `solid` UI payload. Analytic geometry is owned by
`ThroughHoleBrep`; facet triangles are never used for surface definitions.

To inspect or query the B-rep without a Boolean request, use source kind
`analytic_through_hole`, with `origin`, `width`, `height`, `depth`,
`center:[x,z]`, `radius`, and optional `segments`/`tolerance`.

## Acceptance and remaining work

`tests/through_hole.rs` pins analytic volume/area/centroid, full genus-one
incidence and UV ownership, invalid non-through inputs, strong atomicity,
Undo/Redo, semantic arena handles, curved-volume membership and
display-mesh orientation/watertightness/convergence. GitHub Actions
executes this test suite and a JSON CLI smoke test as mandatory gates.

This milestone **does not** enable:

- Generic Boolean operations on arbitrary planar or curved B-reps.
- Multiple disconnected shells, cavities, oblique cylinders, cuts tangent
  to other surfaces, or partial-depth blind holes.
- Boolean application of preview-only `TopologyDeltaPlan`.
- Generic insert/delete/merge of analytic curves and arbitrary UV trim
  segments through Euler commands. The mutable pathway is scoped
  specifically to parameters of this one canonical genus-one feature.
- Persistent feature names across unrelated source regeneration.
- NURBS support or production-grade numerical certification for arbitrary
  CAD topology.

Next gates: an edit-ready heterogeneous curve/trim graph, complete
region arrangements, per-curve local topology journals, face-domain hole
classification and Boolean assembly from multiple face intersections.
